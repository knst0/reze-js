# Plan: Missing framework features

## Goal

Add the features that Solid (1.9 and 2.0), Vue (including Vapor), Svelte and React all have and Reze lacks, in dependency order: context, error boundaries, a `<Suspense>` without a wrapper element, transitions, event replay for lazy islands, a router package, and devtools hooks. Done = each feature below has a public API exported from `reze-js`, works for the client, server (`renderToString`/`renderToStream`) and hydrate targets where applicable, has tests, and does not grow the counter example bundle (apps that do not use a feature do not ship it: checked by `packages/signals/tests/treeShaking.spec.ts`-style tests and `pnpm --filter @rezejs/bench-bundle-size log`).

## Context / constraints

- Follow `AGENTS.md`: no explanatory `//` comments; JSDoc only where the signature cannot state the contract; names carry meaning; no dead code.
- Ownership model (read before starting): an owner is a `ReactiveNode`. `enterOwner`/`adopt` in `packages/signals/src/context.ts` link a child as a *dep* of its owner, so for effect, render (`render.ts`), effect-scope and cleanup nodes the owner is `node.subs?.sub` (first sub link; these nodes have no other subscribers). `root()` (`owner.ts`) creates a `RootNode` with NO link to the current owner. `computed()` nodes are NOT adopted by any owner and their `subs` are their readers. `getOwner()` = `activeSub ?? activeOwner`. `For` rows (`packages/dom/src/list.ts`) and `render()`/`hydrate()` use `root()`; `Show`/`Switch` branches render inside a `computed`.
- Scheduler: writes flush in a microtask (`scheduleFlush`); `flushSync()` flushes now; `batch()` defers.
- Server rendering: `packages/dom/src/server.ts` (`renderToString` wraps in `root` + `withServerRender`); `isServerRender()` in `hydration.ts`. Islands: `hydrateIslands` in `dom.ts`, markers `<!--$id:scope:props:mode-->…<!--/$-->`.
- Runtime feature flags: `crates/reze_compiler/src/features.rs` (`FLAGS`) + `packages/dom/src/features.ts` + the plugin's `Flags` map in `packages/vite-plugin/src/index.ts`. A new flag = entry in all three, so unused features become `false` and tree-shake.
- Static-component classification (`SPEC.md` §15.8): any runtime component (`Show`, `For`, …) makes a component client-side. New runtime components/hooks must be recognized the same way (by symbol, SPEC §8.0) — check `crates/reze_compiler/src/summary/inert.rs` and add the new exports to whatever list names runtime components.
- Compiler spec changes go into `crates/reze_compiler/SPEC.md` (Russian) in the matching section.
- Tests: signals unit tests in `packages/signals/tests/`, DOM e2e through the Vite plugin in `packages/dom/tests/` (happy-dom), hydrate parity in `packages/dom/tests/hydrate.spec.ts`, islands in `packages/dom/tests/islands*.spec.ts`.
- Performance guard: after steps 1 and 2 run `pnpm --filter @rezejs/bench-signals bench` and the DOM rows bench (`benches/dom-rows`, from the performance plan, if already present); regression limit 3 %.

## Steps

- [ ] 1. Owner parent links (foundation for context and error boundaries)
      File(s): `packages/signals/src/context.ts`, `owner.ts`, `computed.ts`; new `packages/signals/tests/owner-parent.spec.ts`.
      Intent: add `export function parentOwner(node: ReactiveNode): ReactiveNode | undefined` in `context.ts`. Add an optional `parent: ReactiveNode | undefined` field to `RootNode` (set to `getOwner()` in `root()`, NOT linked, so disposal semantics stay unchanged) and to `ComputedNode` (set to `getOwner()` in `computed()`). `parentOwner` returns `node.parent` when the node has that field set, else `node.subs?.sub` when `node.dispose !== undefined` (adopted nodes), else `undefined`. Add `export function lookupOwner<T>(pick: (owner: ReactiveNode) => T | undefined): T | undefined` that walks from `getOwner()` through `parentOwner` and returns the first defined `pick` result.
      Done when: tests prove the walk reaches the outer root from: an effect inside a computed inside a root; a `For` row (`root` inside a computed); a `runWithOwner` callback; an `untrack` inside an effect. Signals bench shows ≤ 3 % regression on "create".

- [ ] 2. Context API
      File(s): new `packages/signals/src/contextApi.ts` (keep `context.ts` for tracking internals); `packages/signals/src/index.ts`; `packages/dom/src/index.ts`; new `packages/signals/tests/contextApi.spec.ts`; new `packages/dom/tests/context.spec.tsx`; compiler runtime-component list (see Context).
      Intent: `export interface Context<T> { readonly id: symbol; readonly defaultValue: T; Provider: (props: { value: T; children: JSX.Element }) => JSX.Element }` — `Provider` lives in `@rezejs/dom` because it returns JSX; the signals package exports the core: `createContext<T>(defaultValue: T): Context<T>` (core fields) and `useContext<T>(context: Context<T>): T` and `provideContext<T>(context, value, fn)`. A provider owner is a `ProviderNode` (adopted with `enterOwner`, like `effectScope`) carrying `contextId: symbol` and `value`. `useContext` = `lookupOwner(o => o.contextId === ctx.id ? {value: o.value} : undefined)?.value ?? ctx.defaultValue` (wrap in an object so `undefined` values provided explicitly still win). `Provider` component (in `packages/dom/src/flow.ts`) calls `provideContext(ctx, props.value, () => props.children)`; `value` is read once (document: pass a signal getter for reactive values, like Solid). Server: works unchanged because `renderToString` uses the same owners — add a test. Islands: an island does not see providers outside it (the island hydrates in its own root) — document on `createContext` JSDoc and add compiler `info` diagnostic `CONTEXT_ACROSS_ISLAND` when an island component's module calls `useContext` (optional; if too invasive, only document).
      Done when: tests cover nested providers (inner wins), default value, provider value `undefined`, lookup from inside `For` rows, `Show` branches, async component resumption (`trackAsync` owner), `renderToString`, and `hydrate` parity; the counter bundle size is unchanged.

- [ ] 3. Error boundaries
      File(s): new `packages/signals/src/error.ts` (`catchError`, `handleError`); `packages/signals/src/effect.ts`, `render.ts`, `computed.ts` (catch paths); `packages/dom/src/flow.ts` (`ErrorBoundary`); `packages/dom/src/server.ts`; `packages/dom/src/index.ts`; new tests `packages/signals/tests/error.spec.ts`, `packages/dom/tests/error-boundary.spec.tsx`; new feature flag `errorBoundary` (`__REZE_ERROR_BOUNDARY__`, exports `["ErrorBoundary", "catchError"]`) in the three flag tables.
      Intent: `catchError<T>(fn: () => T, handler: (error: unknown) => void): T | undefined` creates an adopted `ErrorHandlerNode` with a `handler` field, runs `fn` under it in a try/catch (sync errors go to `handler`, return `undefined`). `handleError(owner, error)` walks `lookupOwner`-style from the failing node's owner to the first node with `handler` and calls it; if none, rethrows. `EffectNode.run`, `RenderNode.run` and the initial runs in `effect()`/`renderEffect()` get a `catch (error) { handleError(this, error) }` (the existing `finally` blocks stay); gate the catch body with the feature flag constant so it disappears when the flag is off. `computed` errors propagate to the reader (no change) — they surface in the reader's effect. `ErrorBoundary(props: { fallback: JSX.Element | ((error: unknown, reset: () => void) => JSX.Element); children: JSX.Element })`: a `[error, setError]` signal; a computed that renders `catchError(() => props.children, setError)` when no error, else the fallback (function form receives `reset` = `() => setError(undefined)`, which re-renders children). Server: `renderToString` renders the fallback for errors thrown during rendering inside a boundary; outside any boundary it still throws. Hydrate: if the server rendered the fallback, the client hydrates the fallback branch (serialize a marker `<!--!e-->` before the boundary content on the server; client `ErrorBoundary` in hydrate mode starts in the error state with `error = new Error("server error")` when it sees the marker).
      Done when: tests cover: error in initial render, in an event-driven effect re-run, in a DOM binding, in a nested component inside `For`, reset re-renders, nested boundaries (inner catches), an error in the fallback goes to the outer boundary, no boundary → error still thrown, server fallback + hydrate parity; `flush()`'s queue stays consistent after an error (subsequent writes still update the DOM).

- [ ] 4. `<Suspense>` without a wrapper `<div>`
      File(s): `packages/dom/src/flow.ts` (`Suspense`); `packages/dom/tests/suspense.spec.tsx`; `packages/dom/tests/hydrate.spec.ts`.
      Intent: today `Suspense` returns `[fallback, wrap]` where `wrap` is a `<div>` hidden while pending (`flow.ts`, bottom). Replace with: children are created once into a `DocumentFragment`-backed holder (`insert(holder, children)` where `holder` is a `DocumentFragment`), and the component returns `computed(() => pendingCount() > 0 ? fallbackBranch : childNodes)`, where `childNodes` is the array of nodes currently in the holder or in the document (keep the array of top-level child nodes; on pending, the insert reconciliation moves them out; on resolve, back). Effects inside children keep running while hidden (they are owned by the Suspense owner, not by the branch computed). Behavior change to document in the JSDoc: while pending, children are detached from the document (focus is lost), matching Solid. Server and hydrate: unchanged output shape except no `<div>` — update server emission/hydrate claiming if `renderToString` relied on the wrapper (check `server.ts` and `stream.ts` for `Suspense`).
      Done when: `<table><tbody><Suspense><tr>…` renders valid DOM (no `<div>` in `<tbody>`); tests cover pending → resolved → pending, children's effects not re-run on toggle, nested Suspense, streaming (`stream.spec.ts`) and hydrate parity.

- [ ] 5. Transitions
      File(s): `packages/dom/src/flow.ts` (Suspense boundary registry); new `packages/dom/src/transition.ts`; `packages/dom/src/index.ts`; new `packages/dom/tests/transition.spec.tsx`.
      Intent: semantics = "keep showing current content while new async work is pending" (no forked state, unlike React/Solid 2 — state before and after is the same world). API: `startTransition(fn: () => void): Promise<void>` and `useTransition(): [isPending: Getter<boolean>, start: (fn: () => void) => Promise<void>]`. Implementation: module-level `activeTransition: { pending: Set<SuspenseBoundary>; setPending: Setter<boolean>; resolve: () => void } | undefined`. `start` sets `activeTransition`, runs `fn` inside `batch`, then clears it. In `trackPending` (flow.ts), if `activeTransition` is set when a boundary would be retained AND that boundary has already shown its children once (`hasShownContent` flag on `SuspenseBoundary`), add the boundary to the transition's `pending` set instead of retaining it (so the fallback does not appear); when that boundary's pending work releases, remove it; when the set empties, set `isPending(false)` and resolve the promise. Boundaries that never showed content behave as today (show the fallback).
      Done when: tests: a tab switch wrapped in `start` keeps old content and `isPending()` is true until data resolves, then swaps in one flush; without a transition the fallback shows; two overlapping transitions both resolve; a boundary shown for the first time inside a transition still shows its fallback.

- [ ] 6. Event replay for lazy islands
      File(s): `packages/dom/src/dom.ts` (`watchInteraction`, `hydrateLazy`, `hydrateNow`); `packages/dom/tests/islands-lazy.spec.ts`; JSDoc of `hydrateIslands` (remove "Events that arrive before the code loads are lost").
      Intent: while a lazy island is not loaded, `watchInteraction` also listens (capture, on the island's parent) to the delegated event types (`DelegatedEvents` keys: click, input, change, submit, keydown, keyup, pointerdown, pointerup, focusin, focusout; skip pointermove). For events whose target is inside the island range, record `{ type, target: Element, init }` where `init` copies `bubbles, cancelable, composed, key, code, button, clientX, clientY, shiftKey, ctrlKey, altKey, metaKey`; call `preventDefault()` only for `submit` and for `click` on `<a href>`/submit buttons (to avoid navigation before the handler exists). After `hydrateNow` completes, replay in order: skip if `target.isConnected` is false; re-dispatch with the matching constructor (`MouseEvent`/`KeyboardEvent`/`PointerEvent`/`FocusEvent`/`InputEvent`/`Event`) and the saved `init`; for a replayed `submit` use `form.requestSubmit()`. Hydration claims existing server nodes, so targets stay valid. Keep at most 32 recorded events per island (drop the oldest). Add `hydrateIslands` option `{ replay?: boolean }` default `true`.
      Done when: tests: a click on a `interaction`/`visible`/`idle` island button before load runs the handler exactly once after load; a replayed submit calls the handler and does not navigate; a detached target is skipped; `replay: false` restores the old behavior.

- [ ] 7. Router package `@rezejs/router`
      File(s): new `packages/router/` (`package.json` with `sideEffects: false`, `src/index.ts`, `src/router.tsx`, `src/match.ts`, `tests/`, `vitest.config.ts`, `tsconfig.json`); `pnpm-workspace.yaml` already includes `packages/*`; new example `examples/router/` added to `benches/bundle-size/targets.json`.
      Intent: built on step 2. API: `<Router url?: string base?: string>` (client: History API; server: `url` prop required), `<Route path="/users/:id" component={C}>` with nested `<Route>` children rendered through `<Outlet/>`, `<A href>` (intercepts same-origin left clicks without modifiers, sets `aria-current="page"` when active), `useParams()`, `useLocation()` (reactive getters), `useNavigate()` returning `(to: string, options?: { replace?: boolean }) => void`, and wildcard `*rest` / optional `:id?` segments. Matching in `match.ts`: pre-compiled segment arrays, ranked static > param > wildcard, no regex per navigation. Lazy routes: `component` may be an async component (existing async components, SPEC §7.9) so code-splitting works with `Suspense`; navigation runs in `startTransition` (step 5) so the old page stays visible while the next one loads. SSR: `renderToString(() => <Router url={req.url}>…)` works; hydrate parity. Scroll restoration: scroll to top on push, restore on popstate.
      Done when: tests cover matching ranking, params, nested outlets, `A` click interception, back/forward, lazy route with Suspense + transition, SSR + hydrate; the router example bundle is recorded in bundle-size results.

- [ ] 8. Devtools hooks (phase 1: inspection API, no browser extension)
      File(s): new `packages/signals/src/devtools.ts`; `signal.ts`, `computed.ts`, `effect.ts` (optional `name` in options, dev-only); `packages/dom/src/dom.ts` (`createComponent` records component names in dev); compiler `src/emit/component.rs` (pass the component's name in dev builds only); new `packages/devtools/` (`src/index.ts`: `installDevtools()` exposing `window.__REZE_DEVTOOLS__`); tests.
      Intent: everything behind `process.env.NODE_ENV !== "production"` so production bundles are byte-identical. Dev registry: every node created while devtools are installed gets a `debugName` (explicit `name` option, else the compiler-provided variable name, else `signal#n`). `__REZE_DEVTOOLS__` offers `getOwnerTree(): OwnerTreeNode[]` (walk from registered roots via deps links, labeling component owners by name), `getValue(node)`, `subscribe(listener)` for value changes, and `highlight(element)` returning the owning component. The compiler, in dev only (Vite `serve`), passes `{ name: "count" }` for `const [count, setCount] = signal(0)` and the component name to `createComponent`.
      Done when: a test in dev mode prints a tree `App > Counter > [signal count, render binding ×3]` for the counter example; a production build of the counter example is byte-identical before and after this step.

## Out of scope

- A browser devtools extension/UI (phase 2).
- Router data loaders, actions, file-based routing.
- React-style forked-state transitions or concurrent rendering.
- Server components / resumability.
- Any change to the signal propagation algorithm.
