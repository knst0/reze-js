# Building interfaces

This page covers the features that shape what a component renders and how it responds to input: events, conditional and list rendering, styling, form fields, element references, portals, async views, and islands. Each section gives the rule, an example, and the compiler checks that apply to it.

## Events

Event attributes use camel-case names such as `onClick` and `onInput`. Each takes a handler function that receives the DOM event:

```tsx
import { signal } from "reze-js";

export function Stepper(props: { step: number }) {
  let count = signal(0);
  return (
    <div onClick={() => (count += props.step)}>
      <button>add {props.step}</button>
      <output>{count}</output>
    </div>
  );
}
```

Inside a handler, `currentTarget` is the element that declares the handler, even when the event starts at a child. Calling `stopPropagation()` on the event stops it from reaching ancestors that handle the same event.

### Delegated and direct events

Eleven event types are delegated. Reze installs one listener per type on the `document` and calls the handler on the element that declares it:

- `click`
- `input`
- `change`
- `submit`
- `keydown`
- `keyup`
- `pointerdown`
- `pointerup`
- `pointermove`
- `focusin`
- `focusout`

Every other event attaches its listener directly to the element. For example, `onDoubleClick` listens for `dblclick` on the element itself. A disabled `<button>` does not run its delegated `onClick`. Spread props use the same name mapping.

A lowercase name such as `onclick={save}` compiles to a `click` listener, and the compiler reports `EVENT_NAME_LOWERCASE` as a warning. Rename the attribute to camel case to clear the warning.

```tsx expect=EVENT_NAME_LOWERCASE
export function Save() {
  const save = () => {};
  return <button onclick={save}>save</button>;
}
```

### Pass data to a handler

A two-element array passes data to the handler without a closure:

```tsx
import { signal } from "reze-js";

export function Choices() {
  let picked = signal(0);
  const pick = (id: number) => (picked = id);
  return (
    <p>
      <button onClick={[pick, 1]}>one</button>
      <button onClick={[pick, 2]}>two</button>
      <output>{picked}</output>
    </p>
  );
}
```

For a delegated event, `[handler, data]` calls `handler(data, event)`. For a direct listener, `[handler, options]` passes `options` to `addEventListener`, so `[save, { once: true }]` runs once.

### Listen to any event name

The `on:` prefix attaches a direct listener for the name after the colon, with no camel-case mapping: `on:scroll={onScroll}` listens for `scroll`, and `on:custom={[onCustom, { once: true }]}` listens for `custom` once.

## Conditional rendering

### Inline conditions

Use `&&` or `?:` in JSX for a single condition. The branch builds its nodes when the test becomes truthy and disposes them when the test becomes falsy. While the test stays truthy, the nodes stay in place and their bindings update.

```tsx
import { signal } from "reze-js";

export function Panel() {
  let open = signal(true);
  let text = signal("details");
  return (
    <div>
      <button onClick={() => (open = !open)}>toggle</button>
      <button onClick={() => (text = text === "details" ? "more details" : "details")}>change text</button>
      {open && <p>{text}</p>}
    </div>
  );
}
```

Changing `text` updates the paragraph in place. Setting `open` to `false` removes the paragraph, and setting it back to `true` builds a new one. A ternary such as `{ready ? <b>ready</b> : <i>waiting</i>}` follows the same rule: a change between two values with the same truthiness keeps the nodes, and a flip rebuilds the active side.

### Show and Switch

`Show` renders its children while `when` is truthy and `fallback` otherwise. Without a `fallback`, a falsy `when` renders nothing. A function child receives the tested value as a tracked getter:

```tsx
import { Show, signal } from "reze-js";

export function Greeting() {
  let name = signal("Ada");
  return (
    <div>
      <input value={name} onInput={(e: InputEvent) => (name = (e.currentTarget as HTMLInputElement).value)} />
      <Show when={name} fallback={<p>anonymous</p>}>
        {(value) => <p>hello {value()}</p>}
      </Show>
    </div>
  );
}
```

Clearing the input makes `name` falsy, which shows the fallback.

`Switch` renders the first `Match` whose `when` is truthy, or its `fallback` when none match. It rebuilds only when the chosen `Match` changes:

```tsx
import { Match, Switch, signal } from "reze-js";

export function Status() {
  let code = signal(200);
  return (
    <div>
      <button onClick={() => (code = 404)}>not found</button>
      <Switch fallback={<p>unknown</p>}>
        <Match when={code === 200}>
          <p>ok</p>
        </Match>
        <Match when={code === 404}>
          <p>missing</p>
        </Match>
      </Switch>
    </div>
  );
}
```

A function child of `Match` receives its `when` as a tracked getter, as `Show` does. `Match` works only as a direct child of `Switch`, so use `Show` for a single condition:

```tsx expect=MATCH_OUTSIDE_SWITCH
import { Match } from "reze-js";

export function Ready(props: { ready: boolean }) {
  return (
    <div>
      <Match when={props.ready}>
        <b>ready</b>
      </Match>
    </div>
  );
}
```

## Lists

### Choose a row identity

`For` renders one row per item. Its `keyed` prop decides which rows are kept when `each` changes:

| Mode           | `keyed` value              | Rows follow                  | Row `item` argument   | Row `index` argument      |
| -------------- | -------------------------- | ---------------------------- | --------------------- | ------------------------- |
| Identity       | Omitted, or `keyed={true}` | The item object              | The item itself       | A getter for the position |
| Keyed function | `keyed={(item) => key}`    | The key the function returns | A getter for the item | A getter for the position |
| Position       | `keyed={false}`            | The array position           | A getter for the item | The position as a number  |

The following component renders todos with a function key. Removing a row removes that row's nodes:

```tsx
import { For, signal } from "reze-js";

interface Todo {
  id: number;
  title: string;
}

export function Todos() {
  let todos = signal<Todo[]>([
    { id: 1, title: "write" },
    { id: 2, title: "review" },
  ]);
  return (
    <ul>
      <For each={todos} fallback={<li>empty</li>} keyed={(todo) => todo.id}>
        {(todo, index) => (
          <li>
            {index()}: {todo().title} <button onClick={() => (todos = todos.filter((t) => t.id !== todo().id))}>remove</button>
          </li>
        )}
      </For>
    </ul>
  );
}
```

In keyed-function mode, replacing an item with another object that has the same key keeps the row's nodes and updates its `todo()` getter. Reordering moves the existing nodes. In identity mode, a new object builds a new row. The `fallback` renders when `each` is empty, `null`, `undefined`, or `false`.

Keep keys stable for the lifetime of a row. Use identity mode for stable objects, a keyed function when items are replaced but keep the same logical identity, and position mode when a row belongs to its array slot.

An array literal passed directly to `each` builds new items on every evaluation, so no row can be reused. The compiler reports `INLINE_EACH` as a warning:

```tsx expect=INLINE_EACH
import { For } from "reze-js";

export function Digits() {
  return (
    <ul>
      <For each={[1, 2, 3]}>{(n) => <li>{n}</li>}</For>
    </ul>
  );
}
```

Hoist the array to a module constant, or hold it in a signal.

The compiler reports `KEY_ON_ELEMENT` as a warning when `key` is set on a native element, because `<For>` is the only place rows are keyed:

```tsx expect=KEY_ON_ELEMENT
export function Row() {
  return <li key="a">a</li>;
}
```

### Repeat a fixed count

`Repeat` renders `count` rows, each passed its position as a plain number:

```tsx
import { Repeat, signal } from "reze-js";

export function Placeholders() {
  let count = signal(2);
  return (
    <div>
      <button onClick={() => (count += 1)}>add row</button>
      <ul>
        <Repeat count={count} fallback={<li>none</li>}>
          {(index) => <li>row {index}</li>}
        </Repeat>
      </ul>
    </div>
  );
}
```

A `count` that is not a positive number renders zero rows, and a fraction is truncated. Growing `count` appends rows, and shrinking it removes rows from the end. `fallback` renders while there are no rows.

### Select one row of many

`selector(source)` returns `isSelected(key)`, a function that tells whether `key` is the current value of `source`. Use it when many rows compare themselves with one selection. With the default `Object.is` comparison, each row subscribes to its own key, so a change re-runs only the rows whose answer flipped: the row that was selected and the row that is now selected. The source is a getter, so pass `() => active`, not the signal itself:

```tsx
import { For, selector, signal } from "reze-js";

const tabs = ["home", "docs", "blog"];

export function Tabs() {
  let active = signal("home");
  const isActive = selector(() => active);
  return (
    <nav>
      <For each={tabs}>
        {(tab) => (
          <button class={{ on: isActive(tab) }} onClick={() => (active = tab)}>
            {tab}
          </button>
        )}
      </For>
    </nav>
  );
}
```

Outside a tracked context, `isSelected(key)` returns the current answer without subscribing. A custom `equals(key, value)` replaces `Object.is`. With a custom `equals`, every live key is checked on each change, so the cost grows with the number of rows.

## Styling

`class` accepts a string, `null`, `undefined`, `false`, a toggle object, or an array. `style` accepts a string or an object. The following component toggles a class and sets a width from signals:

```tsx
import { signal } from "reze-js";

export function Badge() {
  let active = signal(false);
  let width = signal(1);
  return (
    <div>
      <button onClick={() => (active = !active)}>toggle</button>
      <button onClick={() => (width += 1)}>wider</button>
      <p class={["btn", { active: active }]}>
        <b style={{ display: "block", width: width + "px" }}>bar</b>
      </p>
    </div>
  );
}
```

A string replaces the `class` attribute. `null`, `undefined`, and `false` remove it. An object adds every space-separated class of each truthy key, so `{ "bg-sky-400 text-white": selected }` toggles both classes together. An array applies its items in order, with nesting allowed. When two object keys name the same class, the later key decides whether it is on.

Object and array values change only the classes that the previous write applied to the element. Classes that other code added stay in place.

A `style` string sets the element's `cssText`. A `style` object takes kebab-case CSS property names. Within the object, `null` and `undefined` remove that property. As the whole value, `null` or `undefined` removes the `style` attribute. In the example, `width` updates when `width` changes and `display` stays as written.

Three prefixes select lower-level writes:

- `bool:hidden={hidden}` toggles the boolean `hidden` attribute.
- `attr:aria-label={label}` writes an attribute. Namespaced names such as `xlink:href` also write attributes. `null`, `undefined`, and `false` remove the attribute.
- `prop:customThing={value}` assigns a JavaScript property with that exact name.

## Forms

Bind the current value to `value` and update the signal from the event that reports the edit:

```tsx
import { signal } from "reze-js";

export function Draft() {
  let draft = signal("");
  let submitted = signal("");
  const submit = () => {
    const title = draft.trim();
    if (title === "") return;
    submitted = title;
    draft = "";
  };
  return (
    <div>
      <input
        value={draft}
        onInput={(e: InputEvent) => (draft = (e.currentTarget as HTMLInputElement).value)}
        placeholder="Something to do"
      />
      <button onClick={submit}>Add</button>
      <p>submitted: {submitted}</p>
    </div>
  );
}
```

On an HTML element, `value`, `checked`, `selected`, `textContent`, and `innerHTML` are written as DOM properties rather than attributes. On a `<select>`, `value` selects the matching `<option>` once the options are in place.

A checkbox bound to a `store` item follows the same pattern. The handler writes the item, and the bindings read it:

```tsx
import { For, store } from "reze-js";

interface Todo {
  id: number;
  title: string;
  done: boolean;
}

export function TodoList() {
  const todos = store<Todo[]>([{ id: 1, title: "write", done: false }]);
  return (
    <ul>
      <For each={todos}>
        {(todo) => (
          <li class={{ done: todo.done }}>
            <label>
              <input type="checkbox" checked={todo.done} onChange={() => (todo.done = !todo.done)} />
              {todo.title}
            </label>
          </li>
        )}
      </For>
    </ul>
  );
}
```

The checkbox reflects `done` through `checked`, the row reflects it through `class`, and the change handler flips the item in place.

### Link labels with createUniqueId

`createUniqueId()` returns an id that is unique on the page. Use it to connect a label to an input in a component that can render more than once:

```tsx
import { createUniqueId } from "reze-js";

export function Field(props: { label: string }) {
  const id = createUniqueId();
  return (
    <div>
      <label for={id}>{props.label}</label>
      <input id={id} />
    </div>
  );
}
```

Each call returns a new id, so call it once per instance. In a client-only build, ids are `r` followed by a number from a module-level counter. In a built page, the id comes from the component's position in the render tree. In the fixture checked for this page, the browser ids after hydration matched the built HTML.

## Element references

`ref` gives you the DOM element after the compiler builds it. Assign the reference to an identifier, to a member of an object, or to a callback:

```tsx
export function Canvas() {
  let canvas!: HTMLDivElement;
  const refs: { bar?: HTMLElement } = {};
  const seen: Element[] = [];
  return (
    <div ref={canvas}>
      <b ref={refs.bar} />
      <i ref={(el: Element) => seen.push(el)} />
    </div>
  );
}
```

After mounting, `canvas` is the `<div>`, `refs.bar` is the `<b>`, and `seen` holds the `<i>`. A callback runs untracked, so reading signals inside it does not subscribe the caller. Read a reference after the element is mounted, such as in an event handler.

## Portals

`Portal` keeps its children in a different parent. Without `mount`, or with `mount={null}`, the children go to the document body. Children stay reactive wherever they are mounted.

This component renders a `<b>` inside a separate `<section>` while `open` is truthy:

```tsx
import { Portal, signal } from "reze-js";

export function Dialog() {
  let open = signal(true);
  let target!: HTMLElement;
  return (
    <div>
      <button onClick={() => (open = !open)}>toggle</button>
      <section ref={target} />
      {open && (
        <Portal mount={target}>
          <b>modal</b>
        </Portal>
      )}
    </div>
  );
}
```

When `mount` is reactive, the same nodes move to the new parent. Children stay reactive after a move, components inside stay alive, and a delegated event inside the portal still reaches its handler. Toggling a portal leaves nothing behind in the mount.

An error thrown while building portal children reaches the nearest `catchError`, the same as an error in inline content. For error handling in general, see [Lifecycle](/lifecycle).

## Async components

An `async` function component awaits data in its body and renders a view when the awaits finish. Attach a `pending` view for the first load and a `failure` view for a rejected await:

```tsx
import { abortSignal, isPending } from "reze-js";

export async function Profile(props: { id: number }) {
  const id = props.id;
  const user = await fetch(`/users/${id}`, {
    signal: abortSignal(),
  }).then((r) => r.json());
  return <p class={isPending() ? "stale" : ""}>{user.name}</p>;
}

Profile.pending = <i>loading</i>;
Profile.failure = (error: unknown, retry: () => void) => <button onClick={retry}>{String(error)}</button>;
```

### Pending and failure views

`pending` renders until the first load settles. During the first load, `isPending()` is `false`. A reload does not show `pending` again. The view runs with `isPending()` set to `true` until the reload settles.

A rejected await renders `failure(error, retry)`. Calling `retry` runs the component again from its start. A `try` around an `await` is a compile error, so let the rejection reach `failure`.

### Abort and pending state

Call `isPending()` in the view. Call `abortSignal()` directly in the load, not in the view. A newer run of the load aborts the signal of the run it supersedes, and the current run's signal stays live. The `fetch` in the example uses it to cancel a stale request.

### Pending boundaries

A component with its own `pending` view shows that view for its own loads, and its parent renders without waiting for it. A component without `pending` shows the nearest ancestor's `pending` view until its own load settles.

### Split code with dynamic import

`await import()` inside an async component loads a module when the component runs, and the `pending` view shows until the import resolves. The three files below show a split chart. `Chart.pending` is set in the file that defines `Chart`:

```tsx file=src/Chart.tsx
import { Skeleton } from "./Skeleton";

export async function Chart(props: { values: number[] }) {
  const values = props.values;
  const { Plot } = await import("./Plot");
  return <Plot values={values} />;
}

Chart.pending = <Skeleton />;
```

```tsx file=src/Plot.tsx
export function Plot(props: { values: number[] }) {
  return <p>{props.values.join(", ")}</p>;
}
```

```tsx file=src/Skeleton.tsx
export function Skeleton() {
  return <p class="skeleton">loading</p>;
}
```

### Rules for async components

The compiler checks the shape of an async component's body:

- Read props into a `const` before the first `await`. A props read inside an awaited expression is a compile error, `ASYNC_PROPS_READ_IN_AWAIT`:

```tsx expect=ASYNC_PROPS_READ_IN_AWAIT
export async function Card(props: { id: number }) {
  const user = await fetchUser(props.id);
  return <p>{user.name}</p>;
}
```

- Do not wrap an `await` in `try`. The compiler reports `ASYNC_TRY_AROUND_AWAIT`, and a rejection goes to `failure`:

```tsx expect=ASYNC_TRY_AROUND_AWAIT
export async function Card(props: { id: number }) {
  const id = props.id;
  try {
    const user = await fetchUser(id);
    return <p>{user.name}</p>;
  } catch {
    return <p>Failed</p>;
  }
}
```

- Call `isPending()` only in the view, and call `abortSignal()` only directly in the load. Other calls are compile errors, `IS_PENDING_OUTSIDE_VIEW` and `ABORT_SIGNAL_OUTSIDE_LOAD`.

## Islands

An island is a component that the page renders before it loads. Reze renders the island's `fallback` first, then loads the component when its trigger fires. Islands use the same loading path as async components, so the `fallback` also renders while a promise from `load` is pending.

There are two ways to write one. The `island()` function takes the loader as an argument. The `island` attribute on a component tag is compiled to a call to `island()` for the client target, and its companion attributes become the arguments.

### Call island

`island(trigger, load, props, fallback?, options?)` returns the island. Its arguments are:

- `trigger`: an `IslandTrigger`, one of `"eager"`, `"idle"`, `"visible"`, `"media"`, or `"interaction"`.
- `load`: a function that returns the component, or a promise for it. It runs when the trigger fires, so `import()` inside it starts the download at that point. With `"eager"`, it runs at once.
- `props`: the props passed to the component.
- `fallback`: an optional function that returns the placeholder, such as `() => <p>loading</p>`.
- `options`: an optional `IslandOptions` object. `media` is the query for the `"media"` trigger, and `rootMargin` is the margin for the `"visible"` trigger.

| Trigger       | Loads when                                                                                            | Renders before loading                                        |
| ------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `eager`       | At once                                                                                               | Nothing, or `fallback` while a promise from `load` is pending |
| `idle`        | On the first idle period, after 2000 ms at most (after 200 ms where `requestIdleCallback` is missing) | `fallback`                                                    |
| `visible`     | When the shell scrolls into view, with `options.rootMargin` around the viewport (default `200px`)     | A `<span data-island="visible">` holding `fallback`           |
| `media`       | When the `options.media` query matches, at once if it already does                                    | `fallback`                                                    |
| `interaction` | On the first `pointerdown`, `focusin`, or `keydown` inside the shell                                  | A `<span data-island="interaction">` holding `fallback`       |

Without a `fallback`, the `visible` and `interaction` shell gets `display:block;min-width:1px;min-height:1px` so that it can be observed.

The examples below use a counter component, defined in its own module:

```tsx file=src/Counter.tsx
import { signal } from "reze-js";

export function Counter(props: { step: number }) {
  let count = signal(0);
  return <button onClick={() => (count += props.step)}>{count}</button>;
}
```

This example renders the counter when it scrolls near the viewport. `load` returns the component through a dynamic import, which starts only when the trigger fires:

```tsx file=src/Page.tsx
import { island } from "reze-js";

export function Page() {
  return (
    <main>
      <h1>Dashboard</h1>
      {island<{ step: number }>(
        "visible",
        () => import("./Counter").then((m) => m.Counter),
        { step: 1 },
        () => (
          <p>loading counter</p>
        ),
        { rootMargin: "400px" },
      )}
    </main>
  );
}
```

A failed load renders the `failure` view of the async component that contains the island. See [Async components](#async-components).

### Use the island attribute

On a component tag, `island` makes the component an island, and the companion attributes configure it:

- `island` by itself, or `island={true}`, is `"eager"`.
- `island="visible"` sets the trigger. The value must be a string literal. A value read from a variable is reported as ISLAND_TRIGGER.
- `islandMedia="(max-width: 40rem)"` is the `media` option, and `island="media"` requires it.
- `islandRootMargin="400px"` is the `rootMargin` option.
- `islandFallback={<p>loading</p>}` is the fallback, written as an element instead of a function.

This dashboard renders the counter with the attribute form and the same fallback:

```tsx file=src/Dashboard.tsx
import { Counter } from "./Counter";

export function Dashboard() {
  return (
    <main>
      <h1>Dashboard</h1>
      <Counter island="visible" islandRootMargin="400px" step={1} islandFallback={<p>loading counter</p>} />
    </main>
  );
}
```

### Split island components

The attribute form moves the component's code into its own chunk when the import line names only that component, the importing file does not export that name, and every use is an island. The compiler then lowers the loader to a dynamic `import()` of that module. Otherwise it reports ISLAND_NOT_SPLIT and keeps the static import.

### Render islands in static output

During a build, an `eager` island renders its component into the HTML. Every other trigger renders only its fallback, inside the `<span data-island>` shell for `visible` and `interaction`, and never calls `load`. The component loads in the browser when its trigger fires. Hydration renders the same shell and arms the trigger.

For `<Counter island="visible" islandFallback={<p>loading counter</p>} />`, the built HTML contains the `data-island="visible"` span with the paragraph inside, and no markup from `Counter`. Static output ignores `islandMedia` and `islandRootMargin`, since the build never loads a non-eager component. To build a site with static output, see [Static site generation](/vite-plugin#static-site-generation).

### Check island diagnostics

The compiler checks the attribute form. An unknown trigger, or a value that is not a literal, is ISLAND_TRIGGER:

```tsx file=src/Sometimes.tsx expect=ISLAND_TRIGGER
import { Counter } from "./Counter";

export function Sometimes() {
  return <Counter island="sometimes" step={1} />;
}
```

The `media` trigger needs the query in `islandMedia`. Without it, the compiler reports ISLAND_MEDIA_MISSING:

```tsx file=src/Responsive.tsx expect=ISLAND_MEDIA_MISSING
import { Counter } from "./Counter";

export function Responsive() {
  return <Counter island="media" step={1} />;
}
```

`island` marks a component tag. On a native element it is reported as ISLAND_ON_ELEMENT:

```tsx expect=ISLAND_ON_ELEMENT
export function Plain() {
  return <section island="visible">hi</section>;
}
```

`islandMedia`, `islandRootMargin`, and `islandFallback` need `island` on the same tag. Without it, the compiler reports ISLAND_ORPHAN:

```tsx file=src/Orphan.tsx expect=ISLAND_ORPHAN
import { Counter } from "./Counter";

export function Orphan() {
  return <Counter islandRootMargin="400px" step={1} />;
}
```

A component that is also used outside an island stays in the main chunk, and the compiler reports ISLAND_NOT_SPLIT:

```tsx file=src/Shared.tsx expect=ISLAND_NOT_SPLIT
import { Counter } from "./Counter";

export function Shared() {
  return (
    <main>
      <Counter island="visible" step={1} />
      <Counter step={2} />
    </main>
  );
}
```
